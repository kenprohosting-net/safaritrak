# SafariTrak screen catalog

This is the Phase 1 inventory for the visual direction in [the design references](../design-system.md). Existing PHP routes are kept. A `planned-screen.php?screen=...` route is an authenticated, clearly labelled roadmap placeholder; it does not implement or simulate the feature.

**Shared acceptance baseline for every screen:** 320px+ mobile and desktop layout; light and dark theme; semantic heading order and labels; keyboard-visible focus; touch-friendly actions; reduced motion; loading, empty, error and offline states where data is loaded; no colour-only status; visible location-sharing scope and revocation; role/record-level server authorisation; no fabricated provider/emergency integration. Per-row acceptance adds the screen-specific behavior. A dash under image means the individual image is pending; the two supplied images are broad visual references, not per-screen evidence.

## Available visuals and mapping policy

Only the two images attached to the request are copied into `docs/design-references/`. They correspond to route/map (broad #07/#18 direction) and a multi-screen mobile collage (broad #05/#14 direction). The collage is not used as one screen reference and no individual images are claimed to exist. The master PDF is retained alongside them. Generate and review one descriptive image per screen later; the screenshot is documentation only, never a page background or production UI.

## Phase 1 route status

Implemented PHP routes remain the source of truth for current behavior. Future-only flows above use an allow-listed `planned-screen.php?screen=...` placeholder and are explicitly labelled. The [roadmap](../implementation/roadmap.md) controls which feature phase may turn each placeholder into a working flow.
